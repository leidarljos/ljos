The seat is about 31k lines of Rust (ljos-cli: one 18k-line lib.rs, an rmcp/tokio MCP server, short-lived hook processes) over five store binaries. Persona sessions open in herdr or tmux (persona_session.rs); decision panels fork headless members (start_decision_panel). The herdr calls predate herdr's current CLI (agent start now needs --kind and --pane; agent send became agent prompt; agent wait takes --until), so open_pane falls back to tmux silently.

Options:
- go-rewrite
- otp-supervision
- tool-adapters
- status-quo

go-rewrite: rewrite the seat in Go so panels and sessions run as goroutines.
otp-supervision: an Erlang/OTP-style supervision model (supervisors, restart strategies, restart intensity) for the seat's long-lived processes: persona panes, panel members, store writers. In Rust, or on the BEAM as a plugin host.
tool-adapters: a declarative integration system for the tools runners live in (herdr, tmux, zellij, headless), declared in harnesses.toml beside the runners, with herdr driven through its current agent API.
status-quo: fix the herdr calls in place and change nothing structural.

Judge by: hook latency and resource cost, what breaks and who notices, migration cost against the crate ecosystem (rmcp, packset-client, vissue-core), and what a person installing the seat has to run.
