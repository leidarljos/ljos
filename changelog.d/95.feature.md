`ljos send` wakes a recipient that is idle, and a running session reads interrupt mail before it stops. Mail waited for the recipient's next prompt, so a Claude Code, Codex or Cursor session that had gone quiet never saw what a Grok Bot sent it. `ljos wake --command CMD` sets a shell line that runs with `LJOS_SEAT` set to the seat, such as `claude -p --resume` or `codex exec resume`, and `ljos wake --webhook URL --key-file FILE` posts the envelope, never the body, to a Grok Bot routine's webhook. `ljos send` and `ljos reply` start that wake in its own session after the message is written, so the sender neither waits nor fails on it, and the guard judges a wake command when it is set and on every run. The `Stop` hook holds a turn once for unread interrupt mail, as `decision: block` or Cursor's `followup_message`, and receipts it. A seat the pack has never heard from is refused with the seat it most likely meant, so `ljos send ljos` asks whether you meant `ljos-bot`.
