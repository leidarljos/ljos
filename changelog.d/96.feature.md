`ljos mcp` serves MCP over stdio by running the `ljos-mcp` installed beside `ljos`, so a client that starts a server by its crate's name reaches it. `tools/list` now gives the core set in a fixed order with the command rules, the consent form and memory first, then the other tools by name, then the persona and playbook tools; it was alphabetical, so `ljos_brief` led the full list and `ljos_claim` the core one. The repository carries the listing files: `server.json` for the official MCP Registry, the `mcp-name` line it checks in the README on crates.io, an `mcp-registry` job in the publish workflow that, once a release tag's crate is on crates.io, publishes the entry with the workflow's OIDC token, `glama.json`, and a `Dockerfile` that builds `ljos-mcp` and starts it.
