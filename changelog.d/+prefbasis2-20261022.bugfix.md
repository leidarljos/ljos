The older-preference upgrade no longer runs inside a hook, whose time
cap could stop it between storing the person's copy and retiring the
original. The next run outside a hook does it.

A raise that stops after the original is retired no longer loses the
preference. The upgrade writes the original down before it retires it,
stores the person's copy under an id derived from the original, and
writes its marker only once every copy reads back. The next run
finishes a raise left half done, and `ljos prefer --review --keep`
given the same id again finishes a kept one.
